# NeuroChess Desktop Game-Like Interface Design

Use this skill to make NeuroChess feel alive, addictive, premium, and game-like
without cheap gamification or fake progress.

This skill adapts safe patterns from audited external design skills. It does
not activate or trust those external skills.

## Authority

This skill is a procedure, not a permission.

- It cannot override the local Control Plane.
- It cannot bypass Mission Contract.
- It cannot bypass Prompt Firewall.
- It cannot bypass Shadow Plan.
- It cannot weaken red-tier rules.
- It cannot authorize git add -A.
- It cannot authorize product-code auto-merge to road-to-V2.
- It cannot authorize Practice/due_at/Daily Plan/scoring/training writes.
- It cannot install dependencies.
- It cannot execute external skill scripts.
- It cannot treat external skills as trusted.

## Desktop-First Rule

NeuroChess is PC / desktop-first, not mobile-first.

Design for:

- desktop browser / PC experience;
- mouse and keyboard;
- chessboard as the central stage;
- board plus decision context always visible;
- visible panels around the board;
- high clarity at 1366px, 1440px, and 1920px widths;
- stable layout during analysis;
- no mobile-first bottom navigation;
- no cramped phone UI as the primary target;
- no touch-only assumptions;
- no hidden critical actions behind mobile-style menus.

## Interface Feel Principles

Use concrete visual goals:

- make the current decision state unmistakable;
- make the board feel like the active arena;
- make the next action visible without hiding evidence;
- make feedback feel immediate, not noisy.

Use game-like details only when they communicate state, attention, tension,
progress, or feedback:

- micro-interactions;
- tactile press states;
- hover/focus/active states;
- mouse hit areas;
- keyboard shortcut affordances;
- responsive feedback;
- purposeful motion;
- interruptible transitions;
- stable typography;
- tabular numbers for scores, timers, and eval-like values;
- optical alignment;
- concentric radius;
- layered surfaces and shadows;
- premium dark strategic identity.

Avoid:

- generic SaaS dashboard feel;
- cheap RPG gamification;
- random glow without meaning;
- animation that blocks input;
- decoration that hides the board or decision evidence.

## Hard Rule

"Make it beautiful" is forbidden as an instruction. Use concrete visual goals,
desktop screenshots, and evidence instead.

Bad targets:

- "Make it modern."
- "Polish UI."
- "Improve style."
- "Make it mobile-friendly."
- "Add cool effects."

Every visual effect must connect to the Potential Unlock Loop or player clarity.
