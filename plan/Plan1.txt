============================================================
0. THÈSE CENTRALE DE NEUROCHESS
============================================================

NeuroChess n’est pas un simple analyseur Stockfish.

NeuroChess n’est pas une app de puzzles génériques.

NeuroChess n’est pas un chatbot d’échecs.

NeuroChess est un système longitudinal d’entraînement échiquéen qui transforme les vraies parties d’un joueur en :

1. diagnostic objectif ;
2. diagnostic pédagogique ;
3. exercices personnalisés ;
4. tentatives mesurées ;
5. révisions espacées ;
6. plan d’entraînement ;
7. validation du transfert en partie réelle.

Phrase fondatrice :

Tes vraies parties révèlent tes décisions.
Tes décisions deviennent des exercices.
Tes exercices deviennent des révisions.
Tes révisions deviennent des compétences.
Tes futures parties vérifient si ces compétences se transfèrent.

Boucle scientifique complète :

PARTIE RÉELLE
→ POSITIONS
→ COUPS
→ ÉVALUATION MOTEUR
→ WIN%
→ PERTE DE CHANCES
→ PRÉCISION
→ SCORE COACH
→ MOMENTS CRITIQUES
→ DIAGNOSTIC
→ TRAINING ITEMS
→ TENTATIVES
→ RÉPÉTITION ESPACÉE
→ MODÈLE UTILISATEUR
→ PLAN RECOMMANDÉ
→ FUTURES PARTIES
→ OPPORTUNITÉS DE TRANSFERT
→ VALIDATION OU NON DU TRANSFERT
→ ADAPTATION DU PLAN

La révolution n’est pas une formule.

La révolution est la boucle fermée :

diagnostiquer
→ entraîner
→ mesurer
→ prescrire
→ vérifier
→ adapter

============================================================
0.1 PROMESSE EXACTE DE NEUROCHESS
============================================================

La promesse de NeuroChess n’est pas :

« Nous garantissons 2400 Elo. »

Cette promesse est interdite.

Un rating autour de 2400 est déjà un niveau extrêmement élevé dans l’écosystème FIDE, associé notamment au niveau de rating requis pour le titre d’International Master, avec des normes et conditions supplémentaires.

La promesse correcte est :

NeuroChess maximise la qualité et la vitesse de progression de chaque joueur en réduisant le temps perdu entre jouer, comprendre, s’entraîner, réviser et transférer en partie réelle.

Formulation ambitieuse autorisée :

NeuroChess donne à chaque joueur un système d’entraînement personnalisé pour exploiter son potentiel le plus vite et le plus profondément possible.

Formulations interdites :

- Tout le monde atteindra 2400.
- NeuroChess garantit un titre.
- Le NeuroScore prédit ton Elo futur.
- NeuroChess mesure ton cerveau.
- NeuroChess mesure ton intelligence.
- NeuroChess mesure directement ta neuroplasticité.

Doctrine finale :

Ambition maximale : oui.
Garantie universelle : non.
Mesure rigoureuse : oui.
Fausse promesse neuroscientifique : non.

0.2 FORMULE FONDATRICE DE LA PROGRESSION
============================================================

La progression utile dans NeuroChess est modélisée conceptuellement par :

Progression utile =
qualité_du_diagnostic
× pertinence_pédagogique
× effort_actif
× répétition_espacée
× transfert_réel
× motivation_durable

Si un facteur tombe à zéro, l’efficacité globale chute.

Exemples :

- Un bon diagnostic sans exercice = analyse passive.
- Un exercice sans tentative active = consommation.
- Une tentative sans révision = oubli.
- Une réussite en exercice sans transfert = progression fragile.
- Un système efficace mais humiliant = abandon.
- Une app agréable mais non mesurée = divertissement.

NeuroChess doit optimiser simultanément :

1. vérité échiquéenne ;
2. science de l’apprentissage ;
3. charge cognitive ;
4. motivation ;
5. mesure longitudinale ;
6. transfert en vraie partie.

Le mot “Neuro” est une marque et une métaphore.

NeuroChess ne mesure pas directement le cerveau.
NeuroChess ne mesure pas l’activité neuronale.
NeuroChess ne mesure pas l’intelligence générale.
NeuroChess ne mesure pas directement la neuroplasticité.

NeuroChess mesure des signaux observables :

- décisions ;
- erreurs ;
- bonnes décisions ;
- pertes de chances ;
- gains de chances ;
- coups candidats déclarés ;
- intentions déclarées ;
- temps de réponse ;
- indices utilisés ;
- solutions révélées ;
- réussites ;
- échecs ;
- coups illégaux ;
- répétitions ;
- exploration locale ;

SCIENCES COGNITIVES DE L’APPRENTISSAGE ÉCHIQUÉEN

Le terme “neurosciences” peut inspirer la marque, mais ne doit pas servir à faire des claims biologiques non mesurés.

============================================================
1.3 PRUDENCE SUR LE TRANSFERT
============================================================

Le transfert est difficile.

Réussir un puzzle ne signifie pas automatiquement réussir en partie.
Réussir une position exacte ne signifie pas maîtriser le motif.
Réussir sans pression ne signifie pas réussir en zeitnot.
Réussir un motif après indice ne signifie pas le reconnaître spontanément.

Doctrine NeuroChess :

1. On ne déclare jamais un transfert sans opportunités détectées.
2. On ne déclare jamais une maîtrise sur une seule réussite.
3. On distingue mémoire, compétence, reconnaissance, exécution et transfert.
4. On distingue transfert proche et transfert lointain.
5. On affiche des signaux prudents, pas des pourcentages trompeurs.

2. DIFFÉRENCIATION STRATÉGIQUE
============================================================

Un LLM générique peut expliquer ponctuellement une position.
Stockfish peut donner le meilleur coup.
Une app de puzzles peut répéter des motifs.

NeuroChess doit faire autre chose :

- comprendre ton historique ;
- identifier tes erreurs récurrentes ;
- identifier aussi tes bonnes décisions ;
- transformer tes erreurs en exercices ;
- mesurer tes tentatives ;
- faire revenir les positions ;
- détecter les opportunités futures ;
- vérifier le transfert ;
- adapter le plan.

Formulation stratégique :

Un analyseur dit : “ce coup est mauvais.”
NeuroChess dit : “ce type de décision revient dans tes parties. Tu l’as réussi en exercice, mais pas encore transféré. On va le retravailler différemment.”

Les cinq défenses stratégiques :

1. vérité moteur versionnée ;
2. mémoire longitudinale ;
3. modèle utilisateur probabiliste ;
4. orchestration pédagogique ;
5. validation du transfert en vraie partie.

NeuroChess doit devenir :

Personal Chess Learning Operating System

Mais sans jargon utilisateur inutile.

6. CONVENTION MOTEUR ABSOLUE
============================================================

Règle :

eval_cp est toujours stocké du point de vue des Blancs.

Donc :

+100 = avantage Blancs
-100 = avantage Noirs

Si une source fournit une évaluation du point de vue du camp au trait, elle doit être convertie avant stockage.

Cette convention est obligatoire pour :

white_percent
player_win_percent
win_loss
move_accuracy
game_accuracy
NeuroScore
criticality
practice
transfer_gap

Sans cette règle, l’app peut inverser silencieusement les scores.

============================================================
7. WIN% LICHESS-LIKE
============================================================

Stockfish parle en centipions.
Les centipions ne sont pas intuitifs pour l’utilisateur.
NeuroChess utilise une transformation Win% lisible.

Formule :

white_percent_lichess_v1 =
100 / (1 + exp(-0.00368208 * eval_cp_white_pov))

Forme équivalente :

Win% =

9. WIN LOSS, GAIN ET DELTA
============================================================

Pour chaque coup du joueur :

raw_win_delta = P_after - P_before
win_loss = max(0, P_before - P_after)
positive_gain = max(0, P_after - P_before)

Pourquoi trois valeurs ?

raw_win_delta mesure la variation brute.
win_loss mesure l’erreur.
positive_gain mesure une bonne décision.

NeuroChess ne doit pas apprendre seulement des erreurs.
Il doit aussi identifier les bonnes décisions reproductibles.

Statut :

metric_id: win_loss_lichess_v1
visible_user: indirect

10. MOVE ACCURACY LICHESS-LIKE
============================================================

Formule :

move_accuracy =
clamp(
  103.1668100711649 * exp(-0.04354415386753951 * win_loss)
  - 3.166924740191411
  + 1,
  0,
  100
)

La constante +1 agit comme bonus/incertitude avant clamp.
À win_loss = 0, la formule dépasse légèrement 100, puis est clampée à 100.

Exemples approximatifs :

| win_loss | accuracy |
|---:|---:|
| 0 | 100 |
| 1 | 96.6 |
| 2 | 92.4 |
| 5 | 80.8 |
| 10 | 64.6 |
| 20 | 41.0 |
| 40 | 15.9 |
| 60 | 5.4 |
| 80 | 1.0 |
| 100 | 0 |

Statut :

Limite :

Une moyenne d’accuracy peut cacher quelques moments très graves.

15. CRITICALITY SCORE V1
============================================================

Rôle :

sélectionner les moments pédagogiquement importants.

Ce n’est pas un score utilisateur.

Formule V1 :

criticality_score =
win_loss
* leverage_weight
* transition_weight
* persistence_weight
* reliability_weight

Statut :

metric_id: criticality_score_heuristic_v1
visible_user: never
drives_training: yes
calibration_status: heuristic_v1

------------------------------------------------------------
15.1 Leverage
------------------------------------------------------------

leverage_weight =
0.75 + 0.5 * (P_before * (100 - P_before) / 2500)

Maximum autour de P_before = 50.

------------------------------------------------------------
15.2 Transition
------------------------------------------------------------

Augmente le poids d’une bascule :

balanced → worse
winning → equal
winning → losing
defensible → lost

------------------------------------------------------------
15.3 Persistence
------------------------------------------------------------

Mesure si la perte reste visible après plusieurs coups.

future_avg =
moyenne player_win_percent sur 6–10 demi-coups

persistent_loss =
max(0, P_before - future_avg)

persistence_weight =
0.75 + 0.5 * clamp(persistent_loss / max(win_loss, 1), 0, 1)

Attention :

persistence observée ≠ causalité parfaite

------------------------------------------------------------
15.4 Reliability
------------------------------------------------------------

Évite de choisir des moments basés sur une analyse faible.

strict_valid analysis => 1.0
weak analysis => 0.8
legacy => low
missing => not candidate

============================================================

11. La difficulté doit être calibrée au niveau et à l’état du joueur.
12. Le plan doit préserver la motivation autant que la performance.
13. Les inférences utilisateur appartiennent à l’utilisateur.
14. Les modèles prédictifs doivent battre une baseline avant de piloter fortement.
