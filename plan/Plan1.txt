============================================================
0. DÉFINITION GLOBALE DE NEUROCHESS
============================================================

NeuroChess est une plateforme d’entraînement aux échecs qui transforme les vraies parties d’un joueur en diagnostic mathématique, en expérience pédagogique guidée, puis en programme de progression personnalisé.

NeuroChess n’est pas seulement un analyseur de parties.

NeuroChess doit devenir un système longitudinal d’entraînement échiquéen capable de :

1. analyser les parties réelles du joueur ;
2. mesurer l’impact objectif de chaque décision ;
3. identifier les moments pédagogiquement importants ;
4. comprendre l’intention déclarée du joueur quand elle est disponible ;
5. comparer intention, coup joué, meilleure ligne et conséquence réelle ;
6. transformer les erreurs en exercices personnalisés ;
7. mesurer les tentatives d’apprentissage ;
8. mettre à jour un modèle probabiliste du joueur ;
9. recommander le prochain entraînement ;
10. vérifier si la compétence apprise se transfère dans les futures parties.

La promesse de NeuroChess n’est pas :

“Voici le meilleur coup.”

La promesse est :

“Voici ce que tes parties révèlent sur ta manière de décider.
Voici ce que tu dois travailler maintenant.
Voici l’exercice.
Voici si tu l’as appris.
Voici si ça se transfère dans tes vraies parties.”

La boucle complète visée est :

PARTIE RÉELLE
→ POSITIONS
→ COUPS
→ ÉVALUATION MOTEUR
→ WIN%
→ PERTE DE CHANCES
→ PRÉCISION
→ NEUROSCORE COACH
→ MOMENTS CRITIQUES
→ INTENTION UTILISATEUR
→ DIAGNOSTIC
→ TRAINING ITEMS
→ TENTATIVES
→ MODÈLE UTILISATEUR
→ PLAN RECOMMANDÉ
→ FUTURES PARTIES
→ VALIDATION DU TRANSFERT

La révolution n’est pas une formule unique.
La révolution est la boucle fermée :

diagnostiquer → entraîner → mesurer → prescrire → vérifier.

1. POSITIONNEMENT SCIENTIFIQUE
============================================================

Le mot “Neuro” est une marque et une métaphore produit.

NeuroChess ne mesure pas directement le cerveau.
NeuroChess ne mesure pas l’activité neuronale.
NeuroChess ne mesure pas l’intelligence générale.

NeuroChess mesure :

- des décisions ;
- des erreurs ;
- des intentions déclarées ;
- des écarts entre intention et réalité ;
- des tentatives d’apprentissage ;
- des temps de réponse ;
- des indices utilisés ;
- des solutions révélées ;
- des réussites et échecs ;
- des progrès ;
- des transferts en vraie partie.

Dans les documents scientifiques internes, le terme exact est :

SCIENCES COGNITIVES DE L’APPRENTISSAGE

plutôt que “neurosciences”.

Les principes mobilisés sont :

- retrieval practice / testing effect ;
- feedback contrastif ;
- error-based learning ;
- desirable difficulty ;
- spaced repetition ;
- interleaving ;
- self-explanation ;
- metacognitive calibration ;
- cognitive load management ;
- transfer learning.

NeuroChess peut utiliser une identité visuelle “neuro”, mais ses claims scientifiques doivent rester prudents.

À dire :

“Nous analysons vos décisions.”
“Nous mesurons des signaux d’apprentissage.”
“Nous identifions des axes de travail.”
“Nous vérifions si l’entraînement se transfère en partie réelle.”

À ne pas dire :

“Nous mesurons votre cerveau.”
“Nous mesurons votre intelligence.”
“Nous garantissons 2400 Elo.”
“Nous mesurons directement la neuroplasticité.”
“Le score mesure vos capacités cognitives globales.”

2. DIFFÉRENCIATION STRATÉGIQUE
============================================================

Question centrale :

Pourquoi NeuroChess plutôt que ChatGPT + Stockfish dans deux ans ?

Réponse :

Un LLM générique peut expliquer une position ponctuelle.
NeuroChess construit un système longitudinal de progression.

ChatGPT + Stockfish peut répondre :

“Pourquoi ce coup est mauvais ?”

NeuroChess doit répondre :

“Tu rates ce type de décision depuis trois semaines.
Tu le réussis en exercice mais tu ne le transfères pas encore en vraie partie.
Voici trois positions issues de tes propres parties pour le travailler.
On vérifiera dans tes dix prochaines parties si le motif revient.”

Les cinq défenses stratégiques de NeuroChess sont :

1. Vérité moteur intégrée
Stockfish est intégré, versionné, contrôlé.
Le LLM ne devine pas les lignes.

2. Mémoire longitudinale
NeuroChess stocke l’historique des parties, erreurs, exercices, tentatives, intentions et progrès.

3. Modèle utilisateur probabiliste
Le système estime progressivement les forces, faiblesses et incertitudes du joueur.

4. Orchestration pédagogique
Le système choisit quoi travailler, quand le revoir et comment le mesurer.

5. Validation du transfert
Le système vérifie si ce qui est réussi en entraînement réapparaît dans les vraies parties.

Formulation stratégique :

Un LLM générique explique une position.
NeuroChess construit un historique, mesure les faiblesses, prescrit l’entraînement, suit les tentatives et vérifie le transfert.

NeuroChess ne doit pas chercher à être “un chatbot d’échecs”.
NeuroChess doit devenir un Personal Chess Learning Operating System.

============================================================

NeuroChess repose sur trois familles de données.

------------------------------------------------------------

------------------------------------------------------------

Pour chaque coup :

- game_id ;
- ply ;
- player_color ;
- side_to_move ;
- FEN avant le coup ;
- FEN après le coup ;
- coup UCI ;
- coup SAN ;
- legal_moves ;
- eval_before_cp ;
- eval_after_cp ;
- mate_before ;
- mate_after ;
- best_move ;
- top_moves ;
- PV ;
- depth ;
- nodes ;
- engine_version ;
- analysis_profile ;
- formula_version ;
- cache_key ;
- created_at.

UCI = notation machine.
Exemples :
e2e4, g1f3, e7e8q.

SAN = notation humaine.
Exemples :
e4, Nf3, Bxf7+, O-O, Qxe8#.

------------------------------------------------------------
3.2 Données d’intention utilisateur
------------------------------------------------------------

Capturées via fenêtres de chat, chips, choix rapides ou Candidate Mode.

Exemples de questions :

- “Quelle idée avais-tu avec ce coup ?”
- “Quelle ouverture voulais-tu jouer ?”
- “Quels coups candidats avais-tu envisagés ?”
- “Quelle réponse adverse avais-tu prévue ?”
- “Quelle menace pensais-tu éviter ?”
- “À quel point étais-tu confiant ?”
- “As-tu joué ce coup par plan, par réflexe ou par manque de temps ?”

Ces données sont subjectives.
Elles ne remplacent jamais l’évaluation moteur.
Elles doivent être horodatées, versionnées, classées pre/post engine, et protégées.

- item_difficulty ;

============================================================
4. CONVENTION MOTEUR : eval_cp POV BLANCS
============================================================

Règle absolue :

eval_cp stocké dans NeuroChess doit toujours être du point de vue des Blancs.

Donc :

+100 = avantage Blancs.
-100 = avantage Noirs.

Si une source moteur fournit une évaluation du point de vue du camp au trait, elle doit être convertie avant stockage.

Cette convention est indispensable pour :

- white_percent ;
- player_win_percent ;
- win_loss ;
- move_accuracy ;
- game_accuracy ;
- NeuroScore ;
- criticality ;
- comparaison Blancs/Noirs ;
- Practice ;
- Transfer Gap ;
- domain signals.

Sans cette convention, les scores peuvent être inversés silencieusement.

============================================================
5. POURQUOI NE PAS UTILISER DIRECTEMENT LES CENTIPIONS
============================================================

Stockfish parle en centipions.

Mais les centipions sont difficiles à interpréter hors contexte.

Exemples :

- perdre 300 cp en position égale peut être catastrophique ;
- perdre 300 cp dans une position gagnante à +8 peut être presque sans importance ;
- perdre 300 cp dans une position déjà perdue peut ne presque rien changer.

L’unité utile pour le joueur est donc :

“Combien de chances de gain ce coup a-t-il fait perdre ?”

C’est pourquoi NeuroChess utilise une sémantique Win% puis Accuracy%.

============================================================
6. WIN% LICHESS-LIKE
============================================================

Formule :

white_percent_lichess_v1 =
100 / (1 + exp(-0.00368208 * eval_cp))

Forme équivalente :

Win% =
50 + 50 * (2 / (1 + exp(-0.00368208 * centipawns)) - 1)

Gestion du mat :

mate_in > 0 => white_percent = 100
mate_in < 0 => white_percent = 0

Statut :

metric_id: white_percent_lichess_v1
purpose: communication / base metric
source_semantics: Lichess-like
calibration_status: external_reference
visible_user: indirect
drives_training: false alone

Attention :

Ce n’est pas une probabilité universelle parfaite.
C’est une courbe empirique utile pour rendre l’évaluation moteur lisible.

============================================================
7. PLAYER WIN%
============================================================

Pour un joueur donné :

Si joueur = Blanc :

player_win_percent =
white_percent

Si joueur = Noir :

player_win_percent =
100 - white_percent

Cela permet d’analyser toujours du point de vue du joueur.

Exemple :

white_percent = 70

Si le joueur est Blanc :
P = 70

Si le joueur est Noir :
P = 30

============================================================
8. WIN_LOSS : PERTE DE CHANCES
============================================================

Pour chaque coup du joueur analysé :

win_loss =
max(0, P_before - P_after)

Exemple :

P_before = 70
P_after = 68
win_loss = 2

Autre exemple :

P_before = 55
P_after = 20
win_loss = 35

Statut :

metric_id: win_loss_lichess_v1
purpose: base metric
visible_user: indirect
drives_training: input to accuracy, criticality, diagnostic

Cette métrique est la base de :

- move_accuracy ;
- game_accuracy ;
- NeuroScore ;
- criticality ;
- domain signals ;
- Practice ;
- Transfer Gap.

============================================================
9. MOVE ACCURACY LICHESS-LIKE
============================================================

Formule :

move_accuracy =
clamp(
  103.1668100711649 * exp(-0.04354415386753951 * win_loss)
  - 3.166924740191411
  + 1,
  0,
  100
)

Interprétation :

- win_loss faible → accuracy haute ;
- win_loss moyenne → accuracy moyenne ;
- win_loss forte → accuracy basse.

Statut :

metric_id: move_accuracy_lichess_v1
purpose: communication
visible_user: indirect
drives_training: false alone

Limite :

L’accuracy pure peut être trop optimiste, surtout si une partie contient beaucoup de coups corrects mais quelques moments critiques très graves.

Si inspiré mais non exact :

Ne pas prétendre à un clone exact de Lichess si l’implémentation ne l’est pas.

11. NEUROSCORE COACH VISIBLE
============================================================

Décision produit finale :

NeuroScore visible =
coach_neuro_score_v1

Formule V1 :

coach_neuro_score_v1 =
0.55 * lichess_like_precision_v1
+ 0.45 * neuro_score_diag_v1

Pourquoi ?

La précision Lichess-like pure est trop flatteuse.
Le diagnostic pur peut être trop démotivant.
Le mix donne une note coach plus équilibrée.

Exemple :

Précision de référence = 87
NeuroDiagnostic = 65

NeuroScore =
0.55 * 87 + 0.45 * 65
= 47.85 + 29.25
= 77.1

UI :

NeuroScore 77 / 100
Score coach

Précision de référence : 87 %

Classification :

metric_id: coach_neuro_score_v1
purpose: communication
visible_user: always
drives_training: false
calibration_status: heuristic_v1
formula_version: coach_neuro_score_v1

Important :

Ce score ne doit PAS piloter les futurs calculs du Learning Engine.
Il est pour l’humain.

Les décisions d’entraînement doivent utiliser :

- win_loss ;
- criticality ;
- tags ;
- practice events ;
- transfer_gap_beta ;
- difficulty_fit ;
- ETV.

Calibration future :

Critère primaire :
pouvoir prédictif sur la performance future.

Le score doit prédire :

- accuracy future ;
- blunder rate futur ;
- missed opportunity rate futur ;
- conversion failure futur ;
- defensive resource missed futur.

Critère secondaire :
ressenti utilisateur, seulement comme garde-fou.

Ne jamais calibrer ce score sur Chess.com, dont la formule exacte n’est pas publique.

Précision de référence : 87 %

============================================================
13. NEURODIAGNOSTIC / NEUROSEVERITY
============================================================

Objectif :

capturer ce que l’accuracy pure ne voit pas assez :

- moments critiques ;
- clusters ;
- conversion ratée ;
- défense manquée ;
- perte persistante ;
- sévérité pédagogique.

Forme conceptuelle :

Pour chaque coup t :

D_t =
L_t * Omega_t

où :

L_t = win_loss

Omega_t = facteur de gravité pédagogique

Omega_t peut intégrer :

- persistence ;
- cluster ;
- conversion issue ;
- defensive resource missed ;
- transition ;
- criticality ;
- post-blunder degradation.

Puis :

Z =
0.65 * mu + 0.35 * tau

où :

mu = moyenne des pertes diagnostiques
tau = perte de queue / moments sévères

Puis :

neuro_score_diag =
100 * exp(-0.035 * Z)

Classification :

metric_id: neuro_score_diag_v1
purpose: audit / internal diagnostic
visible_user: debug_only
drives_training: false until calibrated
calibration_status: needs_corpus

Limite :

Cette famille est fragile tant qu’elle n’est pas calibrée.
Elle empile plusieurs hyperparamètres.
Elle ne doit pas être présentée comme vérité scientifique brute.

14. DIAGNOSTIC GAP
============================================================

diagnostic_gap =
lichess_like_accuracy - neuro_score_diag

Exemple :

accuracy = 87
neuro_score_diag = 65
diagnostic_gap = 22

la précision moyenne est flatteuse, mais le diagnostic interne détecte des moments graves.

Classification :

metric_id: diagnostic_gap_v1

visible_user: debug_only

Ne pas afficher en UI principale.

15. CRITICALITY_SCORE
============================================================

Rôle :

sélectionner les moments pédagogiquement importants.

Ne sert pas à noter publiquement le joueur.

Formule V1 :

criticality_score =
win_loss
* leverage_weight
* transition_weight
* persistence_weight
* reliability_weight

Classification :

metric_id: criticality_score_heuristic_v1
purpose: action
drives_training: true
visible_user: never
calibration_status: needs_corpus

------------------------------------------------------------
15.1 leverage_weight
------------------------------------------------------------

Formule :

leverage_weight =
0.75 + 0.5 * (P_before * (100 - P_before) / 2500)

Rôle :
augmenter le poids des erreurs en position équilibrée.

Maximum autour de P = 50.

À calibrer.

------------------------------------------------------------
15.2 transition_weight
------------------------------------------------------------

Rôle :
pondérer les bascules de zone.

Exemples :

better → balanced
balanced → worse
winning → lost

Statut :
heuristic_v1.

------------------------------------------------------------
15.3 observed_persistence_weight
------------------------------------------------------------

Formule :

future_avg =
moyenne de player_win_percent sur les prochains 6–10 demi-coups

persistent_loss =
max(0, P_before - future_avg)

persistence_weight =
0.75 + 0.5 * clamp(persistent_loss / max(L, 1), 0, 1)

Important :

C’est une persistance observée.
Elle dépend du comportement de l’adversaire.
Elle n’est pas causale.

Future :

counterfactual_persistence_v2
uniquement sur top-3 moments
avec budget Stockfish limité.

------------------------------------------------------------
15.4 reliability_weight
------------------------------------------------------------

Rôle :
éviter d’utiliser une analyse trop faible.

Cible :

- profil requis satisfait : 1.0 ;
- analyse faible : 0.8 ;
- legacy compatible : faible ;
- live/shallow only : non candidat ;
- missing analysis : non candidat.

============================================================
16. VERSION LOG-ADDITIVE FUTURE DE CRITICALITY
============================================================

La formule multiplicative peut amplifier le bruit.

Version future :

log_criticality =
log(win_loss + epsilon)
+ a1 * log(leverage)
+ a2 * log(transition)
+ a3 * log(persistence)
+ a4 * log(reliability)

Avantages :

- plus stable ;
- calibrable terme par terme ;
- compatible avec régression sur corpus annoté.

Test de stabilité :

Pour chaque partie :

- perturber légèrement profondeur/évaluation ;
- recalculer top-5 moments ;
- mesurer Jaccard similarity.

Jaccard(A, B) =
|A ∩ B| / |A ∪ B|

Si Jaccard < 0.6 :
sélection trop instable.

20. PROTOCOLE D’ANNOTATION DE LA TAXONOMIE
============================================================

Avant d’étendre la taxonomie :

Corpus initial :
200 positions.

Annotateurs :
2 personnes si possible.

Mesure :
κ de Cohen.

Formule :

κ =
(p_o - p_e) / (1 - p_e)

où :

p_o = accord observé
p_e = accord attendu par hasard

Seuils :

κ > 0.70 :
taxonomie utilisable.

κ entre 0.50 et 0.70 :
taxonomie ambiguë, définitions à améliorer.

κ < 0.50 :
taxonomie trop confuse, simplifier.

Règle :

Si deux tags sont possibles, définir une règle de désambiguïsation.

Exemple :
Si fork et forcing_sequence sont tous les deux vrais :
primary_tag = forcing_sequence si la séquence complète est nécessaire ;
secondary_tag = fork.

21. DOMAIN SIGNALS BAYÉSIENS
============================================================

Ne pas afficher trop tôt :

Tactique : 62 %
Défense : 48 %

Utiliser des postérieurs bayésiens.

Pour un domaine d :

theta_d ~ Beta(alpha, beta)

Après observations :

theta_d | data ~ Beta(alpha + successes, beta + failures)

Cela donne :

- moyenne ;
- incertitude ;
- intervalle de crédibilité.

Domaines V1 :
- opening ;
- tactical ;
- conversion ;
- defense.

Calculation :
pas de score continu sans logs candidats.

Affichage :

Tactique : prioritaire
Défense : profil en construction
Conversion : stable

Pas de faux pourcentage si données insuffisantes.

Seuils de visibilité prudents :

opening :
>= 10 sessions rehearsal et >= 8 occurrences réelles

tactical :
>= 50 items practice et >= 30 opportunités réelles

conversion :
>= 15 positions gagnantes

defense :
>= 15 positions difficiles

calculation :
>= 100 items avec logs candidats

Sinon :
profil en construction.

============================================================
23. SKILLTRACE BETA V1
============================================================

Modèle utilisateur V1 simple.

Pour chaque concept_tag :

alpha_tag
beta_tag

Prior :

alpha = 2
beta = 2

Mise à jour :

succès sans aide :
alpha += 1.0

succès avec indice :
alpha += 0.5
beta += 0.3

acceptable :
alpha += 0.4
beta += 0.2

échec :
beta += 1.0

solution révélée :
beta += 0.7

skipped :
beta += 0.3 ou no-op

illegal :
beta += 0.5 si lié à incompréhension

Maîtrise :

mastery_mean =
alpha / (alpha + beta)

Incertitude :
intervalle de crédibilité Beta.

Ce n’est pas encore BKT.
C’est une V1 robuste, simple et bayésienne.

============================================================
27. EXPECTED TRAINING VALUE V1
============================================================

Ne pas commencer avec 8 termes.

V1 :

ETV_v1 =
w1 * criticality
+ w2 * difficulty_fit
- w3 * redundancy_penalty

Pourquoi ?

- criticality : moment important ;
- difficulty_fit : bon niveau ;
- redundancy_penalty : éviter répétition excessive.

Les autres signaux sont loggés mais non utilisés au début :

- weakness_match ;
- transfer_relevance ;
- memory_need ;
- information_gain ;
- fatigue_cost ;
- intent_alignment ;
- metacognitive_gap.

V2 future :

ETV_v2 =
w1 criticality
+ w2 weakness_match
+ w3 transfer_relevance
+ w4 difficulty_fit
+ w5 memory_need
+ w6 information_gain
+ w7 intent_signal
- w8 fatigue
- w9 redundancy

Future :
learning-to-rank / contextual bandit.

============================================================
28. DIFFICULTY_FIT
============================================================

Objectif :

P_success autour de 0.60–0.75.

Formule conceptuelle :

DifficultyFit =
exp(-((P_success - target)^2) / (2 * sigma^2))

target ≈ 0.65

Trop facile :
peu d’apprentissage.

Trop dur :
frustration.

Bon niveau :
effort utile.

============================================================
29. TRANSFER GAP BAYÉSIEN
============================================================

Mesure :

réussite en entraînement
-
réussite en vraie partie.

Pour domaine d :

theta_train_d ~ Beta(alpha + s_train, beta + f_train)

theta_practical_d ~ Beta(alpha + s_practical, beta + f_practical)

Delta_d =
theta_train_d - theta_practical_d

Ne pas afficher seulement :

Delta = 27 %

Afficher :

- signal faible ;
- signal moyen ;
- signal fort ;
- profil en construction ;
- intervalle de crédibilité.

Exemple :

L’utilisateur réussit les tactiques en entraînement mais les rate en partie réelle.
Signal de transfert tactique : fort.

30. INTENT LAYER : PRINCIPE GÉNÉRAL
============================================================

L’Intent Layer est un sous-système indépendant.

Il sert à comprendre :

Il ne doit pas être un chat permanent.
Il ne doit pas être obligatoire.
Il ne doit pas remplacer le moteur.

Il doit être :

- opt-in ;
- orchestré ;
- limité en friction ;
- distingué pre_engine / post_engine ;
- ancré textuellement ;
- juridiquement protégé ;
- validé empiriquement.
