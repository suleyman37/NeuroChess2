DOCUMENT MAÎTRE — PLAN 2/3 NEUROCHESS
ARCHITECTURE VISUELLE, UX, PÉDAGOGIE, PARCOURS UTILISATEUR ET DESIGN OPÉRATIONNEL

Version : Plan UX / Produit / Interface v1.0
Objectif : permettre à n’importe quelle IA ou développeur de comprendre précisément comment construire l’expérience utilisateur de NeuroChess, écran par écran, état par état, bouton par bouton.

============================================================
0. DÉFINITION DU PLAN 2
=======================

Le Plan 1 définit comment NeuroChess pense scientifiquement :

* Stockfish ;
* Win% ;
* perte de chances ;
* NeuroScore coach ;
* criticality_score ;
* taxonomie ;
* Practice events ;
* SkillTrace Beta ;
* ETV ;
* Transfer Gap ;
* Intent Layer ;
* sciences cognitives de l’apprentissage.

Le Plan 2 définit comment l’utilisateur vit concrètement l’application.

Le but du Plan 2 est de transformer un moteur mathématique complexe en une expérience :

* claire ;
* belle ;
* motivante ;
* pédagogique ;
* non humiliante ;
* addictive dans le bon sens ;
* respectueuse de la mémoire, de l’attention et de l’émotion ;
* orientée action.

NeuroChess ne doit pas ressembler à un dashboard de métriques.

NeuroChess doit ressembler à un coach calme, exigeant, intelligent et humain.

L’utilisateur ne doit jamais se demander :

“Qu’est-ce que je dois faire maintenant ?”

L’application doit toujours répondre :

“Voici la prochaine action utile.”

============================================================

1. PRINCIPES UX FONDAMENTAUX
   ============================================================

1.1 Une interface fondée sur les moments utilisateur

L’utilisateur ne pense pas en pages.

Il pense en moments :

* Je viens d’arriver.
* J’ai une partie à analyser.
* J’ai perdu et je suis frustré.
* Je veux comprendre ce qui s’est passé.
* Je veux savoir quoi travailler.
* Je veux m’entraîner vite.
* Je veux vérifier si je progresse.
* Je reviens après plusieurs jours.
* Je suis débutant et je ne comprends pas les concepts.
* Je suis avancé et je veux aller plus loin.

Chaque écran doit répondre à un moment émotionnel et cognitif.

1.2 Une page = une intention principale

Chaque écran doit répondre à une question unique.

Aujourd’hui :
“Qu’est-ce que je fais maintenant ?”

Mes parties :
“Quelle partie je veux analyser ou revoir ?”

Review :
“Qu’est-ce que cette partie révèle ?”

Leçon complète :
“Qu’est-ce que je n’ai pas vu ?”

Practice :
“Comment ne plus refaire cette erreur ?”

Entraînement :
“Quelle session je dois faire maintenant ?”

Progression :
“Est-ce que je progresse vraiment ?”

Profil :
“Comment je contrôle mon expérience et mes données ?”

1.3 Complexité cachée, action visible

L’utilisateur ne doit pas voir :

* raw criticality_score ;
* diagnostic_gap ;
* transition_weight ;
* persistence_weight ;
* reliability_weight ;
* raw PV ;
* ETV ;
* BKT ;
* IRT ;
* FSRS ;
* Evidence JSON ;
* posterior Beta ;
* raw Stockfish WDL.

L’utilisateur doit voir :

* NeuroScore ;
* une phrase claire ;
* une priorité ;
* une leçon ;
* un exercice ;
* une progression ;
* une action.

1.4 Hiérarchie simple des actions

Pour chaque écran :

* une action principale ;
* zéro à deux actions secondaires ;
* tout le reste replié, masqué ou dans un menu.

Niveaux visibles :

1. Action principale
   Exemple : “Commencer”, “Voir la Review”, “S’entraîner”.

2. Action secondaire
   Exemple : “Voir le détail”, “Importer une autre partie”.

3. Actions avancées
   Exemple : “Réanalyser deep”, “Voir PGN”, “Debug”, “Supprimer”.

Les actions avancées ne doivent jamais concurrencer l’action principale.

1.5 Respect du temps utilisateur

Objectifs de temps :

* première valeur : moins de 90 secondes ;
* onboarding : moins de 60 secondes ;
* importer/coller une partie : moins de 30 secondes d’action utilisateur ;
* Review rapide : environ 3 minutes ;
* Leçon complète : environ 15–20 minutes ;
* Practice : environ 8–12 minutes ;
* Intent Light : moins de 15 secondes ;
* première compréhension après Review : moins de 10 secondes.

Si une action prend du temps :

* afficher une progression ;
* permettre de quitter ;
* permettre de revenir plus tard ;
* ne jamais bloquer l’utilisateur devant un spinner seul.

1.6 Pédagogie active

NeuroChess doit toujours privilégier :

* essayer avant de voir ;
* comprendre son erreur ;
* rejouer ;
* revoir plus tard ;
* transférer en partie réelle.

Flux pédagogique fondamental :

Défi
→ Tentative
→ Micro-pause
→ Correction
→ À retenir
→ Répétition
→ Révision future
→ Transfert en partie réelle

1.7 Dopamine saine

La motivation doit venir de :

* petites victoires ;
* progression visible ;
* continuité ;
* sentiment de maîtrise ;
* erreurs corrigées ;
* réduction de motifs récurrents ;
* encouragements sincères.

Ne pas utiliser :

* lootboxes ;
* XP arbitraire partout ;
* culpabilisation ;
* feux d’artifice cheap ;
* streaks punitifs ;
* notifications agressives.

2. DÉCISIONS UX FINALES
=======================

2.1 Navigation principale

Navigation V1 :

1. Aujourd’hui
2. Mes parties
3. Entraînement

Profil / Paramètres :
icône en haut à droite.

Review :
ouverte depuis une partie, Aujourd’hui ou une session, mais pas onglet principal permanent.

Progression :
carte compacte dans Aujourd’hui, puis vue détaillée accessible via lien.

2.2 Score principal

Score principal visible :

NeuroScore coach

Ne pas afficher deux grands scores concurrents.

La précision de référence existe, mais dans le détail replié.

UI principale :

NeuroScore 77 / 100
Ta précision moyenne était bonne, mais trois moments critiques pèsent sur la note.

Lien :
Voir le détail du score

Dans le détail :

* Précision de référence : 87 %
* Score coach : précision + gravité des moments critiques
* détails techniques repliés

2.3 Review

La Review n’est pas un espace à quatre onglets équivalents.

Elle est un parcours :

Résumé
→ Lecture rapide ou Leçon complète
→ S’entraîner
→ Explorer seulement si besoin

2.4 Entraînement V1

Trois entrées seulement :

1. Plan du jour
2. Mes positions ratées
3. Révisions

Pas 8 modes en V1.

2.5 Intent Layer

L’Intent Layer est optionnel.

Modes :

* Silencieux ;
* Coach ;
* Candidats.

Jamais permanent.
Jamais obligatoire en Review normale.

2.6 Foundations

Le segment 400–800 est un module spécifique futur.

Pas V1 core.

2.7 Candidate Trainer

Fonction différenciante, mais V2.

Pas V1 core.

3.3 Typographie

Police recommandée :
Inter, Satoshi ou équivalent sans-serif moderne.

Tailles :

* Header app logo : 20–22 px ;
* Navigation : 14–15 px ;
* Hero title Aujourd’hui : 28–32 px ;
* Score Review : 32–36 px ;
* Titre carte : 18–22 px ;
* Texte principal : 15–16 px ;
* Texte secondaire : 13–14 px ;
* Badge : 11–12 px ;
* Debug : 11–12 px, replié.

Ne pas mettre le score Review à 56 px.
56 px réservé à la landing marketing.

3.4 Spacing

Global app padding desktop :
24–32 px.

Card padding principale :
20–24 px.

Card padding compacte :
14–16 px.

Gap principal :
20–24 px.

Gap secondaire :
12–16 px.

Gap compact :
8 px.

3.5 Border radius

Panels :
18–22 px.

Cards :
16–18 px.

Buttons :
10–12 px.

Badges :
999 px.

3.6 Ombres et glow

Utiliser glow avec parcimonie.

CTA principal :
box-shadow: 0 0 24px rgba(25,217,255,0.22);

Panel actif :
box-shadow: 0 0 0 1px rgba(25,217,255,0.22);

Ne jamais mettre glow sur toutes les cartes.

3.7 Boutons

Bouton principal :

* hauteur : 44–48 px ;
* padding horizontal : 18–22 px ;
* fond gradient cyan/blue ;
* texte dark ou white selon contraste ;
* font-weight 700 ;
* border-radius 12 px.

Bouton secondaire :

* hauteur : 40–44 px ;
* fond transparent ou panel-soft ;
* border subtle ;
* texte main.

Bouton tertiaire :

* texte ou petit bouton ;
* faible poids visuel ;
* jamais en compétition avec CTA.

Bouton destructif :

* couleur danger ;
* confirmation modale obligatoire.

3.8 États hover/focus

Hover :
légère montée de luminosité + border cyan.

Focus clavier :
outline cyan 2 px, visible.

Disabled :
opacity 0.45, cursor not-allowed.

9. REVIEW — LECTURE RAPIDE
==========================

Objectif :
comprendre en 3 minutes.

Pas de défi.
Pas d’exercice obligatoire.
Pas d’Intent Layer.
Pas de Candidate Trainer.

Flux :

Moment 1 :

* coup joué ;
* meilleur coup ;
* une phrase ;
* impact.

Moment 2 :
idem.

Moment 3 :
idem.

À la fin :

Texte :
Tu veux transformer cette lecture en entraînement ?

Boutons :

* M’entraîner maintenant
* Me le rappeler demain
* Terminer

Si “Me le rappeler demain” :
créer rappel doux.

Si “Terminer” :
Aujourd’hui peut proposer 24–48h plus tard :
Tu as lu cette Review. Tu veux rejouer les 2 moments clés ?

But :
éviter que Lecture rapide devienne un divertissement sans apprentissage.

10. REVIEW — LEÇON COMPLÈTE
===========================

Objectif :
apprentissage actif.

Flux par moment :

1. Défi
2. Tentative
3. Micro-pause
4. Correction
5. À retenir
6. Entraînement / moment suivant

10.1 Défi

Visible :

* échiquier ;
* coup / position ;
* phrase courte ;
* boutons Indice, Voir correction, Passer.

Texte :
Coup 23 — à toi de jouer
Trouve l’idée qui change la position.

Pas visible :

* solution ;
* PV ;
* score ;
* difficulté ;
* diagnostic ;
* source longue.

Intent Mode toggle :

* Silencieux
* Coach
* Candidats

Silencieux :
aucune question.

Coach :
question légère, skippable.

Candidats :
active Candidate Trainer pour ce moment.

10.2 Tentative

L’utilisateur joue sur le board.

Si bon coup :
feedback positif.

Si mauvais :
micro-pause.

10.3 Micro-pause

Si coup incorrect :

Pause 2–3 secondes.

Message :
Observe ce que ton coup permet à l’adversaire.

Puis correction.

10.4 Correction

Structure :

Ton coup

* notation ;
* conséquence.

Meilleure idée

* notation ;
* idée.

À retenir

* règle courte.

Boutons :

* Continuer
* Réessayer
* Rejouer la ligne

Comparer lignes :
replié.

10.5 Entraînement

Texte :
Cette idée mérite d’être ancrée.

CTA :
S’entraîner maintenant

Secondaire :
Moment suivant

Mode focus.

* Position X / Y
* progress bar discrète
* échiquier

  Voir la correction
  Passer

* source ;
* thème détaillé ;
* difficulté ;
* diagnostic ;
* score ;

11.2 Timer

Mesuré en interne.

Afficher chrono, optionnelle.

11.3 Indices

Indice 1 :
oriente sans révéler.

Indice 2 :
plus précis.

Indice 3 :
proche solution.

Après indice 3 :
Voir la solution.

11.4 Après tentative

Si correct :
“Bien joué. Tu as trouvé l’idée.”

Si incorrect :
micro-pause, puis correction.

11.5 Fin session

Résumé :

Session terminée

* 5 positions tentées
* 3 réussies sans aide
* 1 avec indice
* 1 à revoir

Message :
Les positions ratées vont revenir. C’est exactement comme ça qu’on consolide.

CTA :
Revoir les ratées

Secondaire :
Retour à Aujourd’hui

12. RÉPÉTITION ESPACÉE
======================

V1 = FSRS-lite simple.

Règles :

Raté :
revoir demain.

Réussi avec indice :
revoir dans 3 jours.

Réussi sans aide :
revoir dans 7 jours.

Réussi plusieurs fois :
intervalle plus long.

UI :
Prochaine révision : dans 3 jours.

Très important :
réviser aussi par motif, pas seulement position exacte.

Si motif = fork :
proposer plus tard :

* position exacte ;
* position similaire ;
* autre position avec même motif.

V1 :

28. VERDICT FINAL
=================

NeuroChess ne doit pas être seulement clair.
Il doit être aligné avec la cognition humaine.

L’utilisateur doit :

* comprendre vite ;
* se sentir guidé ;
* essayer avant de voir ;
* recevoir un feedback au bon moment ;
* ne pas être humilié ;
* revoir avant d’oublier ;
* revoir le motif dans plusieurs contextes ;
* sentir une progression réelle ;
* garder un minimum d’autonomie.

La différence entre une app propre et une app révolutionnaire se joue dans :

* le timing du feedback ;
* la charge cognitive ;
* la répétition ;
* la régulation émotionnelle ;
* l’autonomie ;
* la preuve de progression.

Formule finale :

NeuroChess doit être clair en 5 secondes,
utile en 90 secondes,
actif en 3 minutes,
consolidant en 48 heures,
motivant en 7 jours,
mesurable en 30 jours,
transformateur en 6 mois.
