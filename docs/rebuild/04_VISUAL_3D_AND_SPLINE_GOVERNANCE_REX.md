# Visual 3D And Spline Governance REX

## Doctrine

Spline/3D n'est pas une couche decorative globale. Spline/3D est un langage d'identite et de progression, uniquement apres validation.

La 3D doit etre rare, utile et reliee a une surface produit claire. Si une carte 2D suffit, la 3D n'est pas justifiee.

## Regles

- Tout asset 3D commence en Visual Lab DEV-only.
- Aucun asset 3D n'entre en produit sans role clair.
- Aucun asset 3D au centre du board.
- Aucun asset 3D comme feedback permanent de coup.
- Aucun cerveau humain comme representation du joueur.
- Pas de fake neuroscience.
- Pas de 3D si une carte 2D suffit.
- Lazy loading obligatoire.
- Fallback 2D obligatoire.
- Reduced motion obligatoire.
- Validation humaine visuelle obligatoire.
- Pas de dependance critique au CDN pour utiliser l'app.

## Surfaces Autorisees

- Profil ;
- onboarding ;
- loader d'analyse ;
- recompense rare ;
- constellation de repertoire ;
- trophee/rang ;
- cristal de transfert.

## Surfaces Interdites

- board central ;
- card permanente dans Parties sans role ;
- feedback de coup systematique ;
- CTA principal ;
- Review si cela nuit a la decision.

## Checklist Promotion Asset

Un asset 3D ne peut sortir du Visual Lab que si tous les points suivants sont vrais :

- role utilisateur clair ;
- metrique reliee ;
- contexte rare ;
- performance acceptable ;
- fallback accessible ;
- wording safe ;
- screenshot valide humainement ;
- pas de pollution UI ;
- `GO_FOR_PROMOTION` explicite.

## Statut Des Explorations Connues

- Brain Core actuel : quarantaine, non promu.
- Living Stage Spline : experimental, non base produit.
- Constellation/repertoire/profil : piste prioritaire.

## Regle De Langage

La 3D peut representer une progression, un rang, un repertoire, une memoire systeme ou un objet de recompense. Elle ne doit pas representer le cerveau du joueur, une mesure cognitive directe ou un diagnostic mental.
