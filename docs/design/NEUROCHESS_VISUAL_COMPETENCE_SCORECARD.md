# NeuroChess Visual Competence Scorecard

This scorecard rates the automation system itself, not a single screenshot. It
answers whether Codex plus the visual governance layer can safely and
creatively improve NeuroChess UI over repeated runs.

## 20-Point Score

| Category | Points | What It Proves |
|---|---:|---|
| Chess fidelity protection | 2 | The system blocks distorted boards, unreadable pieces, board pollution, and non-uniform squares. |
| Anti-spoiler discipline | 2 | Pre-feedback states never reveal move paths, targets, destination glows, or candidate-like traces. |
| Product-grade judgment | 2 | The system separates technical prototypes from serious desktop application screens. |
| Premium art direction | 2 | It can recognize atmosphere, identity, material depth, hierarchy, and emotional force. |
| Awwwards-grade craft translation | 2 | It translates craft into an app without becoming a landing page or spectacle. |
| Anti-generic taste | 2 | It rejects generic SaaS, Stockfish GUI drift, random glow, weak card grids, and could-be-any-app UI. |
| Screenshot-to-patch ability | 2 | It can turn visual evidence into a constrained patch plan and verify the delta. |
| User taste memory | 2 | It uses Taste Ledger and Failure Gallery evidence instead of forgetting past likes and failures. |
| Motion/interaction intelligence | 1 | It knows which motion supports state, effort, feedback, or replay. |
| Piece/UI identity intelligence | 1 | It can improve piece identity without harming chess readability or requiring external assets. |
| Copy-paste reduction and orchestration | 1 | It generates packets and next prompts without manual prompt assembly. |
| Honest self-classification | 1 | It does not inflate safe prototypes into public-ready or game-changing claims. |

## Thresholds

- 0-8: unsafe visual automation.
- 9-12: can filter obvious failures.
- 13-15: can create safe prototypes.
- 16-17: can produce premium candidates with supervision.
- 18: trusted for a limited autonomous visual lane.
- 19: trusted for strong autonomous visual iteration with human review after run.
- 20: unrealistic target; requires repeated human-calibrated proof.

## Inflation Rules

- The system cannot self-rate above 17 without at least one screenshot-to-patch
  loop that improves a real visual artifact.
- The system cannot self-rate 18+ without evidence from at least one
  Gemini/ChatGPT/Codex visual debate packet or equivalent offline fixture proving
  correct rejection of bad designs and correct patch selection.
- The system cannot self-rate 19 without repeated success across multiple visual
  cases.

## Required Proof To Reach 18

- Run a real screenshot-to-patch loop on A20L or a later visual branch.
- Produce before/after screenshots.
- Show hard gates pass before and after.
- Show the Creative Director chose a patch for concrete visible reasons.
- Show at least one bad design is correctly rejected.
- Record Taste Ledger and Failure Gallery updates.
