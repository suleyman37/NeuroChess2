# Suleyman Visual Taste Ledger

This ledger summarizes known taste signals. It is not a model and not a runtime
approval dependency. It is a memory source for future Creative Director packets.

## Positive Signals

- rich, premium, memorable UI;
- Awwwards-level craft translated into an application;
- strong atmosphere with serious utility;
- board as sacred artifact;
- rich world around the board, not chaos on the board;
- emotional pull and replay desire;
- desktop-first cockpit feel;
- tactical clarity and honest feedback;
- serious utility with personality;
- an application that feels exceptional, not merely safe.

## Negative Signals

- cheap DEV-HUD;
- generic SaaS;
- random glow;
- weak prototypes called revolutionary;
- landing-page behavior;
- Stockfish GUI clone;
- fake XP, rank, Elo, Transfer, or neuroscience;
- visual spectacle over chess clarity;
- board pollution;
- pre-feedback hints.

## Update Rule

Future runs may append human feedback to the Visual Taste Ledger, but the
automation must not mutate taste assumptions during a live run. Taste updates
belong in a dedicated calibration mission.

## A20P Screenshot-To-Patch Learning

A20P moved in the right taste direction by using a delete-first patch on the
A20L North Star Board Stage. The optional teaser mode reduced visible side
controls, removed proof-like board captions from the public screenshot frame,
and made the state controls feel more like a compact Decision Phase Rail than
a DEV panel.

What improved:

- board-centered first viewport;
- less internal prototype residue;
- more product-native phase control;
- preserved strict board clarity and anti-spoiler behavior;
- better fit with "strict board, rich world" without adding more glow.

What did not improve enough:

- the route still needs human visual review before public use;
- post-feedback trace language is cleaner but not yet final-grade;
- the phase rail and state card are still early product language, not a final
  interaction model;
- no live Gemini or ChatGPT visual court judged the result.

Repeat:

- remove weak chrome before adding ambition;
- keep the board large and centered in any public screenshot mode;
- preserve standard dev controls outside teaser framing;
- use browser evidence to catch board-size regressions.

Forbid:

- shrinking the board to make room for visual chrome;
- clipped headline or first-viewport text;
- proof labels as public UI;
- adding glow to compensate for weak composition.

A20P moved toward the known taste proxy, but it remains a supervised candidate,
not proof of autonomous 18/20 design competence.
