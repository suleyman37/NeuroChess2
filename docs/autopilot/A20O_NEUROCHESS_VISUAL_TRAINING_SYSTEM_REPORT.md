# A20O NeuroChess Visual Training System Report

## 1. Mission Summary

A20O created the NeuroChess Visual Training System: a dry-runable design
competence layer for Creative Director decisions, Awwwards-grade app craft,
visual debate, screenshot-to-patch loops, taste memory, failure memory, visual
primitive rules, and copy-paste reduction.

This mission did not implement product UI and did not run A21, Night Mode, or a
3h rehearsal.

## 2. Why A20N Was Insufficient For Design 18/20

A20N was safe and useful, but conservative. It produced design governance, not a
real visual improvement loop. It did not run a screenshot-to-patch cycle, did
not compare before/after screenshots, and did not prove the system can select a
visual patch from competing critiques.

## 3. Current Visual Automation Score Estimate

Current estimate after A20O: 16/20.

Reason:

- hard gates and failure memory are strong;
- Creative Director 2.0 and visual debate now exist;
- dry-run scripts and fixtures can reject bad designs and generate next prompts;
- no real screenshot-to-patch run has improved an actual visual artifact yet.

The system cannot claim 18/20 yet.

## 5. Creative Director 2.0 Summary

Creative Director is now the art-direction synthesizer. It chooses between
surviving directions after hard gates pass. It cannot override chess fidelity,
anti-spoiler semantics, Control Plane safety, or product truth.

## 6. Awwwards-Grade App Benchmark Summary

The benchmark translates Awwwards craft into desktop app criteria:
composition, hierarchy, material depth, interaction, motion, scene identity,
emotional pull, usability, accessibility, and chess clarity.

## 7. Visual Debate Protocol Summary

The protocol defines evidence packet, Gemini visual perception, ChatGPT
product/art critique, Chess Arbiter, Anti-Generic Critic, Codex Patch Planner,
and Creative Director verdict rounds. Live providers are off by default.

## 8. Screenshot-To-Patch Loop Summary

The loop converts screenshots into defects, patch options, a selected patch,
new screenshots, and delta comparison. It stops after stagnation and forbids
endless CSS tweaking.

## 9. Visual Training Gym Summary

The gym defines drills for sacred board protection, no-hint tension,
delete-first cleanup, rich world building, anti-generic UI, Awwwards
translation, feedback dignity, piece identity, motion meaning, and public
teaser honesty.

## 10. Taste Ledger Summary

The Taste Ledger captures known user taste: rich premium UI, serious utility,
Awwwards-level craft as application quality, rejection of cheap dev-HUD,
generic SaaS, random glow, and weak prototypes called revolutionary.

## 11. Failure Gallery Summary

The Failure Gallery records A20H/A20H2, A20J, A20J3, A20L, and A20N failures so
future missions can detect similar problems earlier.

## 12. Visual Primitive Registry Summary

The registry maps primitives to zones, freedom levels, board-crossing rules,
move-implication risk, and post-feedback requirements.

## 13. Radicality Budget Summary

Radicality is near zero in the board core and high in the surrounding stage.
This keeps the board strict while allowing the world around it to become
expressive.

## 14. No Generic Glow Law Summary

Every glow must have source, state, zone, function, intensity, and a reason it
cannot be mistaken for a move hint.

## 15. Motion Doctrine Summary

Motion is state-bound: calm observe, contained try tension, success
stabilization, miss reorientation, and replay memory.

## 16. Design Token Constitution Summary

Tokens must be semantic. Random colors, random glow, and unsupported visual
tokens are forbidden.

## 17. Piece Identity Brief Summary

Pieces must be readable, premium, non-letter-disc for North Star claims, and
code-native or internal unless a future asset mission permits otherwise.
