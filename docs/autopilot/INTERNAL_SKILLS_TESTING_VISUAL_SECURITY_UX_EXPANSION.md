# Internal Skills Testing Visual Security UX Expansion

A16L2 adds four internal procedures that turn recent audit findings into
NeuroChess-specific operating rules.

## Testing And Visual Proof

The `neurochess-testing-visual-proof` skill should be selected for frontend
branches, browser smokes, screenshot evidence, contact sheets, visual proof,
and morning UI branch review. It requires desktop viewport proof, console and
network capture when browser smokes run, route/state evidence, and failure
screenshots.

It does not authorize package installs, visual baseline tooling, frontend
auto-merge, or execution of external browser automation scripts.

## Security And Repo Hygiene

The `neurochess-security-repo-hygiene` skill should be selected for automation,
Git, local config, external skill, package, script, CI, and repo hygiene work.
It enforces explicit staging, denies destructive Git patterns, protects secrets
and browser profiles, keeps quarantined external content local, and requires
dedicated missions for package or CI changes.

## Product UX Critique

The `neurochess-product-ux-critic` skill should be selected for product-facing
missions and UX prioritization. It asks whether the work solves a real player
problem, reduces friction, creates a first 30 seconds aha moment, clarifies
what the player should do now, and keeps desktop chess decisions readable.

It rejects dark-pattern retention, fake progress, fake neuroscience, fake
Elo/XP/rank/Transfer claims, and novelty without player value.

## Learning Loop Acceleration

The `neurochess-learning-loop-accelerator` skill should be selected for work
that affects review, practice, training, feedback, onboarding, or player-facing
learning value. It requires each mission to name the Potential Unlock Loop step
it advances and prefers active effort before explanation.

## Night Mode Use

Future Night Mode can use the expansion as procedural guidance:

- frontend branches use testing visual proof;
- all runs observe security repo hygiene;
- product mission selection uses product UX critique;
- player-facing work uses learning-loop acceleration;
- morning reports summarize evidence, incidents, player value, and learning
  progress.

These skills are procedures, not permissions, and they remain below the
deterministic safety gates.
