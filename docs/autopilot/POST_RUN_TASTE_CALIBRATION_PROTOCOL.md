# Post-Run Taste Calibration Protocol

Autonomous design judgment improves after the run, not during the run.

Post-run flow:

1. Collect screenshots and contact sheets as external artifacts.
2. The user may mark outcomes as `LOVE`, `LIKE`, `NEUTRAL`, `DISLIKE`, or
   `REJECT`.
3. Append feedback to the Visual Taste Ledger.
4. Run a dedicated calibration mission to update the Suleyman Taste Proxy.
5. Validate the updated proxy with deterministic tests.

Forbidden during live runs:

- changing the taste proxy;
- waiting for user visual approval;
- accepting a generic winner because the user is unavailable;
- using a screenshot as evidence if it is not indexed or reviewable.

Calibration lets the system get sharper without breaking autonomy.
