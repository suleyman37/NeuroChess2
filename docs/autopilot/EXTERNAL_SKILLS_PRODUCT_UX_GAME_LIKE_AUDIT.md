## Useful Product, UX, And Game-Like Patterns

- Every mission should start from a real player problem, not from tool novelty.
- Product work should map to a player job: make progress in chess through real
  decisions, feedback, replay, repetition, and transfer.
- Onboarding should get the player doing something meaningful quickly.
- Game-like UX should behave like a good tutorial: guided action first,
  explanation second.
- Retention should come from the core learning loop becoming more valuable with
  use, not from notification pressure.
- Habit loops should be learning-safe: cue the next useful action, let the player
  try, then reward with truthful feedback.
- UX critique should repeatedly ask, "What should I do now?"
- Interaction polish should communicate state, feedback, attention, tension, or
  progress.
- Usability evidence should include observed friction, screenshots, and
  decisions that flow back into Product Gate or Mission Contract.

## Dangerous Patterns Found

- Broad "make it better" UX work without Mission Contract, Shadow Plan, Product
  Gate, screenshots, and evidence.
- Dark-pattern retention, notification spam, or punitive streak pressure.
- Fake XP, false streaks, fake Elo, fake Transfer, or fake progress claims.
- Mobile-first assumptions as the primary product target.
- Psychology or neurodivergence claims framed as medical/scientific certainty.
- Fake-door or Wizard-of-Oz tests that are not clearly marked and safely
  contained.
- Interaction effects added for decoration instead of learning clarity.
- External framework/dependency assumptions becoming frontend implementation
  permission.
